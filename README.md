# CrashTrace

A small user-mode debugger for Windows that helps you figure out why a program crashed, exited on its own, or hung.

## Quick Summary

- Built to diagnose problems in games and software, across all languages.
- It has a graphical interface. It is not a command-line tool.
- Still under development, but **version 1.0 works well** and has been genuinely useful.
- The **"Can I Run It?"** feature is **incomplete**. It does not work reliably yet. It's on the roadmap, but not ready.
- AI assisted with parts of the code. It did not write the whole project. All the code comments were generated by AI.

---

## What it does

CrashTrace launches a target program under the Windows debugging API, watches every event from the first instruction, and when something goes wrong, produces a detailed report explaining what happened.

The report covers:

- The type of failure (crash, silent exit, abnormal exit, or hang)
- The exception code and meaning
- The faulting module, offset, CPU registers, and memory state at the crash site
- A mini-disassembly of the instructions around the fault
- A screenshot and a minidump of the moment of the crash
- A list of missing DLLs and runtime dependencies
- Loaded modules, active threads, Windows Event Log entries, and WER reports

It also includes two standalone static analysis tools: **DLL Scan** and **Can I Run It?** Both inspect a file without ever running it.

CrashTrace is **fully offline by design**. It never connects to the internet and never sends any data anywhere.

---

## How to read the report

The report has several sections. One of them, **"WHAT YOU SHOULD TRY"**, is worth a word of caution.

That section is a **legacy system**. It was an early attempt at giving the user automatic fix suggestions. It is still in the code, and it still produces output, but the suggestions are **preliminary and generic**. They are not tailored to the specifics of your crash. Do not treat them as a diagnosis.

The real value is in the rest of the report. The status code, the faulting module, the memory state, the disassembly, the call stack, and the dependency analysis - those are the parts that describe what actually happened. Read those first. If you are pasting the report into an AI assistant, tell it to focus on the technical sections and ignore "WHAT YOU SHOULD TRY".

The section may be improved or replaced in future versions.

## A word about antivirus software

> **CrashTrace will almost certainly trigger your antivirus.**

This is expected. It is not a false alarm in the sense that the antivirus is broken - it is doing its job. But it is a false positive in the sense that CrashTrace is not malware.

Here is why it gets flagged:

- It uses `CreateProcess` with `DEBUG_ONLY_THIS_PROCESS`. This is the API a debugger uses to take control of another program. Some malware does the same thing.
- It calls `ReadProcessMemory` on the target. Malware also does this to extract credentials or secrets from other processes.
- It calls `MiniDumpWriteDump`, which writes a full memory dump of a process. This is exactly what credential-stealing tools do.
- It hooks into a running process's event stream, watches every DLL load, and reads raw memory around fault addresses.

Any one of these on its own would be enough to raise a flag. Together, they look, from the antivirus's point of view, exactly like the early stages of a memory-scraping attack.

### What can happen

Depending on your antivirus:

- Windows Defender may silently quarantine or delete `CrashTrace.exe` or one of the helper executables right after you extract the archive.
- Third-party antivirus products (Avast, Kaspersky, Bitdefender, etc.) may do the same, or may show a warning every time you run it.
- The file may disappear without any notification. If you extracted it and it's not there a minute later, the antivirus almost certainly removed it.

### What to do

1. Open your antivirus settings and add an **exclusion** for the folder where CrashTrace lives.
2. If the antivirus already deleted the files, restore them from the quarantine (most products have a "Restore" option in their quarantine view), or re-extract the archive.
3. If restoration does not work, temporarily disable real-time protection, re-extract the archive, add the exclusion, then re-enable protection.
4. In some cases, Windows Defender's "Controlled folder access" feature may also block the tool. Check Windows Security -> Virus & threat protection -> Ransomware protection and add an exclusion there too.

The source code is fully available in this repository. Every file that gets flagged is right here for you to read.

## Development environment

| Component | Version |
|-----------|---------|
| Language | C# |
| Framework | .NET Framework 4.5 |
| UI | Windows Forms |
| IDE | Visual Studio 2010+ / SharpDevelop 4.4+ |
| Target platform | Windows (x64 host) |

External libraries used:

- **SharpDisasm** - x86/x64 disassembler (C# port of udis86)
- **Microsoft.Diagnostics.Runtime (ClrMD)** - reads managed exceptions from .NET processes

The tool ships with two helper executables to handle .NET exception reading across architectures:

- `TestAppHelper32.exe` (x86) - for 32-bit managed targets
- `TestAppHelper64.exe` (x64) - for 64-bit managed targets
